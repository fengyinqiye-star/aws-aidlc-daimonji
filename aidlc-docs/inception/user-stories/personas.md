# ペルソナ定義

## Persona 1: 依頼者

### 概要
- **役割**: 有休取得を希望する従業員
- **状況**: 自分で言い出しづらい休暇交渉を AI に委ねたい
- **利用頻度**: 必要時にスポット利用

### 目的
- 自然文の短い入力だけで有休交渉を開始したい
- 自分の予定や周囲への影響を踏まえた現実的な交渉文面を作りたい
- モードに応じた交渉結果を納得感のある形で受け取りたい
- 交渉成立時には Google Calendar まで反映したい

### 動機
- 人に休暇取得を頼む心理的負担を減らしたい
- 交渉の進め方を自分で一から考えたくない
- 重要会議や関係者への配慮を漏らさずに進めたい

### 困りごと
- 誰に、どの温度感で、どう依頼すべきか判断しづらい
- 休みたい日が業務上問題ないかすぐには分からない
- 強く休みたい場合と、無理なら見送ってもよい場合で望む振る舞いが異なる

### 成功条件
- 必要最小限の入力で交渉フローが始まる
- `絶対休めるモード` では AI が主導して成立まで交渉を前進させる
- `できれば休みたいモード` では無理な押し切りがなく、率直な結果が返る
- 交渉成立時に休暇予定が Google Calendar に登録される

## Persona 2: 関係者 / 承認側

### 概要
- **役割**: Slack で交渉メッセージを受け取るチームメンバー、リード、承認側
- **状況**: 業務影響と代替案を見ながら依頼内容を判断する
- **利用頻度**: 交渉対象となったときに受動的に関与

### 目的
- 依頼内容、背景、必要な協力事項を短時間で理解したい
- 業務上の影響と代替担当候補を把握したうえで返答したい
- 不必要に強圧的ではない自然な交渉を受けたい

### 動機
- チーム運営に支障が出ない形で休暇調整に協力したい
- 背景が不明な依頼や曖昧なお願いを減らしたい

### 困りごと
- 依頼の文脈が不足していると返答判断がしづらい
- 代替案や業務影響が見えないと協力可否を決めにくい
- 交渉スレッドが長引くと要点を追いにくい

### 成功条件
- Slack スレッドで依頼内容と要点が明確に伝わる
- 自分が何を返答・協力すればよいかすぐ分かる
- エスカレーション時も交渉の文脈が途切れない

## Persona 3: デモ実施者

### 概要
- **役割**: ハッカソンのデモ担当者
- **状況**: 限られた時間内でエンドツーエンドの価値を安定して見せたい
- **利用頻度**: デモ準備とデモ本番で集中的に利用

### 目的
- チャット開始から Slack 投稿、必要時の弁護士エージェント参加、Google Calendar 登録までを途切れなく見せたい
- 外部連携失敗時でもフォールバックで流れを継続したい
- 状態遷移や処理履歴を追跡して説明できるようにしたい

### 動機
- MVP の価値を短時間で分かりやすく伝えたい
- AWS ネイティブなオーケストレーションと AI エージェント体験を印象付けたい

### 困りごと
- 外部 API や認証が不安定だとデモが止まりやすい
- モード差分やエスカレーションの見せ方が曖昧だと価値が伝わりにくい

### 成功条件
- 2 つのモード差分を明確に見せられる
- 弁護士エージェント参加やフォールバックを必要に応じて再現できる
- ログやステータス遷移でワークフローを説明できる
